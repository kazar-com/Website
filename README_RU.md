# KAZAR — рабочая локальная сборка

## Обновление запуска и готовности staging

Исправлен entry point через `fileURLToPath(import.meta.url)`. Регрессия действительно запускает дочерний сервер из папки с пробелами, `#` и `%` и проверяет HTTP-ответ. Node.js 24.19.0 / Linux: 8 тестов PASS. Windows-пути проверены с `windows:true`; нативный запуск Windows не выполнен. На Windows выполните те же команды ниже в PowerShell из распакованной папки с пробелами, затем `node --test tests/*.test.mjs`.

Добавлены проверенные локально backup/restore и модуль повторных отправок уведомлений. Последний испытан только с синтетическим транспортом: реальный провайдер не подключён, отправка и получение email НЕ подтверждены. Статус `PROVIDER_ACCEPTED` не означает получение в ящике. Сохранённая заявка не зависит от результата отправки.

Браузерная QA и staging остаются BLOCKED: нет доступного защищённого развёртывания; прежний изолированный браузерный просмотр не подключился к серверу. HTTP-тесты не заменяют проверку кликов, телефона, фокуса и сетевого retry в браузере.

Резервная копия SQLite снимается online; восстановление — только в новую папку:

```sh
node scripts/backup.mjs backup .data private-backup-01
node scripts/backup.mjs restore private-backup-01 restored-data-01
```

После восстановления остановите сервер, задайте `DATA_DIR` как абсолютный путь к `restored-data-01` через защищённое окружение или `.env`, запустите сервер и проверьте записи командой оператора. Копия включает секрет сессий; папка должна оставаться приватной. Не включайте её в исходники, веб-каталог или пересылаемый архив. TLS, дисковое шифрование, внешнее резервирование и Windows ACL проверяются на выбранном хостинге, а не предполагаются готовыми.

Утверждённые pages.json, HTML-компоненты, CSS и оригинальные SVG перенесены из KAZAR_FOR_WEB_DEVELOPER.zip. Геометрия логотипов и approved.css сохранены побайтно. Это реализация для локальной проверки, не опубликованный сайт.

## Запуск

Требуется Node.js 24.x. Внешних npm-зависимостей нет; npm install не требуется.
Распакуйте архив, откройте терминал в папке `kazar-implementation`:

```sh
node scripts/build.mjs
node server/local.mjs
```

Откройте **http://127.0.0.1:3000/** в браузере этого компьютера.
Остановка: Ctrl+C. Повторный запуск сохраняет ранее созданную базу.
Если используете `.env`, скопируйте `.env.example` в `.env` и запускайте:

```sh
node --env-file=.env server/local.mjs
```

Команды npm `npm run build`, `npm start`, `npm test` — эквивалентные удобные варианты.

## Проверить основной путь

1. Home → Services либо Private Clients / For Architects.
2. Arrange a project discussion → Contact.
3. Отправьте пустую форму: появятся ошибки полей.
4. Введите только синтетические данные: имя `Synthetic Review`, email `review@example.com`, выбранную стадию, краткое тестовое описание.
5. Отправьте. Подтверждение появляется после реальной записи в `.data/enquiries.sqlite` и возвращает идентификатор заявки.
6. Add project details → заполните любые необязательные сведения → Save project details. Эти данные дополняют ту же заявку.
7. Finish for now / Skip сохраняет первоначальную заявку. Прямая ссылка на подтверждение без действующей сессии возвращает на Contact.
8. Для проверки сети откройте Contact, заполните поля, остановите сервер и отправьте: ошибка должна сохранить значения. Запустите сервер и повторите отправку из той же формы. Не очищайте данные вкладки между попытками.

Это тестовые заявки: email не отправляется и никто из команды не получает уведомления. Локальная запись — не доставка письма.

Просмотр сохранённых тестовых записей уполномоченным оператором:

```sh
node scripts/enquiries.mjs
node scripts/enquiries.mjs ENQUIRY_REFERENCE
```

База, внутренний секрет и тестовые записи находятся вне отдаваемой веб-папки, не входят в архив. Не пересылайте их вместе с сайтом. В таблице notification_outbox заявки отмечены NOT_CONNECTED. Автоматического отправителя почты пока нет.

## Автоматические проверки

```sh
node --test tests/*.test.mjs
```

Проверки создают отдельную временную БД с синтетическими данными, проверяют HTTP-маршруты, валидацию, сохранение, повторные запросы, перезапуск, ограниченный доступ и отказ хранилища. Временная тестовая БД удаляется после проверки.

Браузерная проверка текущей сборки не завершена: изолированный браузер не смог подключиться к локальному серверу. Нативные Chrome / Safari / Edge, iOS / Android, клавиатура и адаптивные размеры требуют отдельной проверки. Это не результаты staging или production QA.

## Что работает

Home, Services, Private Clients, For Architects & Designers, KAZAR Standard, About, Project Diagnostic, Contact; Projects и закрытый демонстрационный Case Study template; legal review pages; 404.

Реальные URL, оригинальная адаптивная CSS-база, мобильное меню, native details/summary для 8 стадий, серверная выдача HTML, одинаковая клиентская/серверная валидация, состояния ожидания/ошибки, повтор без потери введённого, запись SQLite с FULL synchronous, idempotency, scoped HttpOnly session, опциональный Step 2, сохранение после перезапуска.

## Пока не подключено

- Почтовый сервис и обработчик очереди уведомлений; CRM не выбран.
- Private upload storage и сканирование. Поле загрузки отключено; остальные поля Step 2 работают. Контракт: до 5 PDF/JPEG/PNG, до 20 MB каждый, до 50 MB суммарно. При подключении обязательны серверная проверка содержимого и контроль доступа.
- Частный Diagnostic Intake: страница доступа существует, запись закрыта. Нужен механизм приглашений после согласования scope.
- CMS-редактор: утверждённые схемы включены, административный интерфейс не создан.
- Hosting/staging, production backups/monitoring и согласованное хранение данных.

## Решения / доступ от владельца

1. Назначить ответственного разработчика и предоставить ему приглашение к выбранному staging-хостингу с постоянным хранилищем. Новые платные услуги — только после согласования стоимости.
2. Выбрать почтовый сервис, дать доступ через приглашение / защищённую настройку окружения; получатель уведомлений — утверждённый info@kazar.build. Пароли и ключи не передавать в чат.
3. Утвердить сроки хранения/удаления заявок, роли доступа и тексты privacy / terms перед public launch.
4. Предоставить разрешения на изображения и настоящий портрет. Al Furjan не снимать с HOLD автоматически.

Публичный домен https://kazar.build и email info@kazar.build уже утверждены. Повторное согласование этих фактов не нужно. DNS, почтовая маршрутизация, редиректы и действующий сайт не изменялись.
